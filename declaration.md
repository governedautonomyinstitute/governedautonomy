# Governed Autonomy

Governed Autonomy enables useful agent work within explicit, enforceable and reviewable authority across systems.

Governed Autonomy defines architectural requirements for keeping autonomous agent actions within approved mission-scoped authority as agents work across systems. It coordinates identity, policy, execution controls, human intervention, evidence and delegation. Adopters authorize missions and own policy and factual assumptions. Implementations demonstrate the applicable controls within a declared boundary.

## Abstract

Governed Autonomy specifies runtime governance for agent work across systems. Governing functions check applicable authority and material conditions before an effect and recheck them before commitment where conditions can change. Existing identity, access, policy, security and infrastructure controls supply many of these functions. The doctrine organizes their use around approved missions, bounded effects, cross-system handoffs, intervention and reconstructable evidence. A deployment baseline, use-case assurance profile and separate organizational maturity evaluation support precise claims. Conformance does not prove factual truth, legal compliance or universal safety.

## What Governed Autonomy Governs Against

Autonomous agents introduce a threat surface that existing enterprise security was not designed to see. The risks are operational, active, and scaling with every new agent deployment.

Prompt Injection

Malicious input hijacks agent reasoning, not code. The agent follows instructions exactly as designed. The instructions have been replaced.

Intent Hijacking

An action aligned with an invalid or manipulated purpose or mission context. Governance evaluates observable effects against approved mission constraints; it cannot read internal motivation.

Cascading Failure

A single corrupted assumption propagates across interconnected workflows at machine speed: a systemic failure before humans can intervene.

Behavioral Drift

Gradual departure from sanctioned behavior through accumulated context or manipulation. Point-in-time audits cannot detect what changes slowly.

These four categories organize attention; they are not an exhaustive threat model. They bear on what an agent does with the authority it holds, so authority is checked before each effect, not only at access.

## The Doctrine

Three principles are non-negotiable:

Governance operates in the execution path, at the time relevant conditions must hold

Enforcement covers the declared cross-system effect boundary rather than a fragment the agent can bypass

Agents operate under **Least Agency**: no greater decision scope or authority than their approved missions require
